## 1. 前提条件・準備情報

券商から以下のFIX接続情報を入手してください：

| 項目 | 説明 | 例 |
|------|------|-----|
| `BeginString` | FIXバージョン | `FIX.4.2` / `FIX.4.4` / `FIXT.1.1` |
| `DefaultApplVerID` | アプリバージョン（FIXT.1.1のみ） | `FIX.5.0SP2` |
| `SenderCompID` | こちらの識別子 | `TRADEX_CLIENT` |
| `TargetCompID` | 券商側の識別子 | `BROKER_SERVER` |
| `SocketConnectHost` | 接続先ホスト | `fix.broker.com` |
| `SocketConnectPort` | 接続先ポート | `9000` |
| `HeartBtInt` | ハートビート間隔（秒） | `30` |
| `Username` | ログオン用ユーザー名 | `user123` |
| `Password` | ログオン用パスワード | `secret` |
| SSL使用有無 | TLS接続かどうか | `Y` / `N` |

> **セキュリティ注意**: `Password`などの機密情報は設定ファイルに直接書かず、環境変数または`docker/secrets/`のシークレットファイルで管理してください。

## 3. application.ymlへのセッション登録

`src/main/resources/application-dev.yml`（または本番環境の設定ファイル）に以下を追加します：

```yaml
flashtrade:
  fix:
    sessions:
      # 既存セッション ... (省略)
      
      # 新しい券商のセッション
      - session-key: acme-broker          # 一意のキー（英数字-ハイフン）
        broker-name: ACME Broker          # 表示名
        config-file: fix/sessions/acme-broker-initiator.cfg  # リソースパス
        enabled: true
        fix-version: FIX.4.4              # FIX.4.2 / FIX.4.4 / FIXT.1.1
```

### 設定項目の説明

| キー | 型 | 必須 | 説明 |
|------|-----|------|------|
| `session-key` | String | ✓ | FixBrokerClient識別子。英数字とハイフンのみ |
| `broker-name` | String | ✓ | ログ・APIレスポンスで使用する表示名 |
| `config-file` | String | ✓ | classpath相対のCFGファイルパス |
| `enabled` | boolean | ✓ | `false`にすると起動時にセッションをスキップ |
| `fix-version` | String | ✓ | `FIX.4.2` / `FIX.4.4` / `FIXT.1.1` のいずれか |

## 4. FixBrokerClientのSpring Bean登録

`src/main/java/com/tradex/flashtrade/fix/config/FixGatewayAutoConfiguration.java`に以下を追加します：

### 4.1 既存コードの参考パターン

```java
// 既存のセッションに対してFixBrokerClientがどのように生成されているかを確認し、
// 同じパターンで新しいBeanを追加します。
// FixGatewayAutoConfigurationはセッション設定リストを読み取り、
// 各セッションに対してFixBrokerClientをBean登録します。
```

### 4.2 自動登録の確認

`FixGatewayAutoConfiguration`は`flashtrade.fix.sessions`リストを走査し、`enabled=true`のセッションについて自動的に`FixBrokerClient`を生成・登録します。**手動でBeanを追加する必要はありません。**

設定後にアプリを起動し、以下のログが出力されれば登録成功です：

```
INFO  FixGatewayAutoConfiguration - FIX session registered: acme-broker (ACME Broker) [FIX.4.4]
INFO  FixApplicationHandler - Session created: FIX.4.4:TRADEX_CLIENT->BROKER_TARGET_COMP_ID
```

## 5. FIXバージョン別の機能差異

| 機能 | FIX 4.2 | FIX 4.4 | FIX 5.0 SP2 |
|------|---------|---------|-------------|
| 行情（Market Data） | ✅ | ✅ | ✅ |
| 新規注文（placeOrder） | ✅ | ✅ | ✅ |
| 注文キャンセル（cancelOrder） | ✅ | ✅ | ✅ |
| 注文修正（Order Modify） | ✅ | ✅ | ✅ |
| 注文状態照会（getOrderStatus） | ✅ | ✅ | ✅ |
| 成交履歴（getTrades） | ❌ ※1 | ✅ | ✅ |
| ポジション照会（getPortfolio） | ❌ ※2 | ✅ | ✅ |

**※1 FIX 4.2の`getTrades()`**: TradeCaptureReport（MsgType=AE）はFIX 4.2では未サポートのため、ローカルに記録した成交履歴（`ExecutionReport`から生成）のみを返します。  
**※2 FIX 4.2の`getPortfolio()`**: `UnsupportedOperationException`をスローします。FrontendはFIX 4.2接続時にポジション取得機能を無効化してください。

## 6. カスタムフィールドの対応

券商が独自のカスタムフィールド（Tag番号 5000〜9999）を使用する場合：

### 6.1 Logon時のカスタムフィールド

`FixApplicationHandler.java`の`toAdmin()`メソッドを修正します：

```java
@Override
public void toAdmin(Message message, SessionID sessionID) {
    String msgType = message.getHeader().getString(MsgType.FIELD);
    if (MsgType.LOGON.equals(msgType)) {
        // 標準フィールド
        message.setString(Username.FIELD, username);
        message.setString(Password.FIELD, password);
        
        // カスタムフィールドの例（Tag 9999 = カスタム認証トークン）
        if ("acme-broker".equals(getSessionKey(sessionID))) {
            message.setString(9999, customAuthToken);
        }
    }
}
```

### 6.2 注文送信時のカスタムフィールド

該当バージョンの`Fix44MessageAdapter.java`（または`Fix42`, `Fix50`）の`toFixNewOrderSingle()`内に追加：

```java
// カスタムフィールド（Tag 8001 = 取引口座タイプ）
newOrder.setString(8001, "MARGIN");
```

## 7. DataDictionary（データ辞書）のカスタマイズ

カスタムフィールドを使用する場合、データ辞書XMLを修正する必要があります。

### 7.1 ファイルパス

QuickFIX/Jのデータ辞書はJARに内包されていますが、カスタム辞書を配置することでオーバーライドできます：

```
src/main/resources/FIX44.xml   (FIX 4.4 カスタム辞書)
src/main/resources/FIX42.xml   (FIX 4.2 カスタム辞書)
src/main/resources/FIX50SP2.xml (FIX 5.0SP2 カスタム辞書)
```

### 7.2 カスタムフィールドの追加例

`FIX44.xml`にカスタムフィールドを追加：

```xml
<!-- fields セクションに追加 -->
<field number='8001' name='AccountType' type='STRING' />

<!-- messages セクションの対象メッセージに追加 -->
<message name='NewOrderSingle' msgtype='D' msgcat='app'>
  <!-- 既存フィールド ... -->
  <field name='AccountType' required='N' />
</message>
```

### 7.3 CFGファイルの参照先変更

`DataDictionary=FIX44.xml` → `DataDictionary=custom/acme-FIX44.xml`（別ファイルにする場合）

## 8. SSL/TLS設定

券商がSSL/TLS接続を要求する場合、CFGファイルに以下を追加します：

```ini
[SESSION]
# ... 既存設定 ...
SocketUseSSL=Y
SocketKeyStore=fix/ssl/keystore.jks
SocketKeyStorePassword=${FIX_KEYSTORE_PASSWORD}
SocketTrustStore=fix/ssl/truststore.jks
SocketTrustStorePassword=${FIX_TRUSTSTORE_PASSWORD}
```

### 証明書ファイルの配置

```
src/main/resources/fix/ssl/
  keystore.jks      ← クライアント証明書
  truststore.jks    ← 券商のCA証明書
```

> **注意**: `keystore.jks`および`truststore.jks`はGitにコミットしないでください。`.gitignore`に追加し、デプロイ時に安全な方法で提供してください。

## 9. テスト手順

### 9.1 ローカルテストAcceptorを使う

`application-dev.yml`で以下を設定してください：

```yaml
flashtrade:
  fix:
    test-server:
      enabled: true   # テスト用Acceptorを起動
```

テスト用Acceptorは`FIX.4.2`で動作し、以下のメッセージに応答します：

| メッセージ | 動作 |
|-----------|------|
| NewOrderSingle (D) | `NEW`ステータスの`ExecutionReport`を返却 |
| OrderCancelRequest (F) | `CANCELED`の`ExecutionReport`を返却 |
| OrderCancelReplaceRequest (G) | `REPLACED`の`ExecutionReport`を返却 |
| OrderStatusRequest (H) | 現在ステータスの`ExecutionReport`を返却 |
| MarketDataRequest (V) | モック価格（100〜999の固定値）のスナップショットを返却 |

### 9.2 統合テストの実施手順

1. アプリを起動：
   ```bash
   ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev
   ```

2. ヘルスチェックAPI確認：
   ```bash
   curl http://localhost:8080/api/v1/fix/sessions/status
   ```
   `LOGGED_ON`が表示されれば接続成功

3. 行情取得テスト：
   ```bash
   curl -X POST http://localhost:8080/api/v1/market-data \
     -H "Content-Type: application/json" \
     -d '{"symbols": ["7974", "9984"], "broker": "test-local"}'
   ```

4. 注文テスト：
   ```bash
   curl -X POST http://localhost:8080/api/v1/orders \
     -H "Content-Type: application/json" \
     -d '{
       "symbol": "7974",
       "side": "BUY",
       "orderType": "LIMIT",
       "quantity": 100,
       "limitPrice": 5000,
       "broker": "test-local"
     }'
   ```

## 10. トラブルシューティング

### 10.1 セッションが接続できない

**症状**: ログに`Connection refused`または`Logon timeout`

**確認事項**:
- `SocketConnectHost`と`SocketConnectPort`が正しいか
- ファイアウォールでポートが開放されているか
- `HeartBtInt`が券商の要求値と一致しているか
- `LogonTimeout`を長く設定（例：`30`）

```ini
HeartBtInt=30
LogonTimeout=30
ReconnectInterval=10
```

### 10.2 ログオン拒否（Logon Rejected）

**症状**: `Logout`メッセージが返ってくる、または`Text`フィールドに拒否理由

**確認事項**:
- `SenderCompID` / `TargetCompID`が正しいか
- `Username` / `Password`が正しいか（環境変数の設定漏れ確認）
- `ResetOnLogon=Y`でシーケンス番号リセットが必要か
- `CompID`に大文字小文字の違いがないか

### 10.3 メッセージ送信後に応答がない

**症状**: `placeOrder()`がタイムアウト（デフォルト30秒）

**確認事項**:
- セッションが`LOGGED_ON`状態か（`/api/v1/fix/sessions/status`確認）
- `ValidateIncomingMessage=N`を設定（券商の独自フィールドを無視）
- ログファイル（`./logs/fix/[broker-name]/`）でFIXメッセージのRaw確認
- `DataDictionary`のカスタムフィールド定義漏れがないか

### 10.4 FIX 4.2でgetPortfolio()がエラーになる

**原因**: FIX 4.2ではPositionReport（MsgType=AP）がサポートされていません。

**対処**: FIX 4.4またはFIX 5.0SP2に切り替えるか、UI側でポジション機能を非表示にしてください。

### 10.5 ログの確認方法

```bash
# FIXメッセージのログ
tail -f ./logs/fix/[broker-name]/FIX*.log

# アプリケーションログ
tail -f ./logs/spring-boot.log | grep -i fix
```

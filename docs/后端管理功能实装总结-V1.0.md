## 🏗️ 架构设计

### 数据库架构（V19迁移）
```
orders（已增强）
├── 管理字段：admin_note, risk_flag, admin_id, admin_action_time
├── 交易字段：limit_price, filled_quantity, average_price, total_value, commission
└── 其他字段：broker_account_id, preview_id, external_order_id

审计表
├── operation_log - 记录管理员操作（CREATE, UPDATE, DELETE等）
├── login_log - 记录登录事件（成功/失败，IP跟踪）
├── api_call_log - 记录API调用（响应时间，关键操作标记）
└── system_event_log - 记录系统事件（错误、告警，severity级别）

统计表
├── order_daily_summary - 每日订单统计
└── log_retention_policy - 日志保留策略
```

### 业务流程

**订单管理流程**
```
用户下单 → OrderAdminController.queryOrders()
       → OrderAdminService查询订单（支持多维过滤）
       → 异常检测 → 标记订单（📝 WARN log）
       → 取消订单（⚠️  WARN log）
       → OperationLog记录所有修改
```

**审计日志流程**
```
所有API请求 → ApiCallLogAspect（@Around AOP）
         → 提取用户、IP、响应时间
         → 异步记录ApiCallLog（不阻塞请求）
         → 标记是否关键操作、是否出错

管理员操作 → OrderAdminService/AuditLogger.logOperation()
       → 记录before/after值，操作摘要
       → OperationLog持久化

系统错误 → 任意异常点 → AuditLogger.logSystemEvent()
     → 记录severity（LOW/MEDIUM/HIGH/CRITICAL）
     → SystemEventLog持久化
```

## 🔍 关键日志标记

### Emoji 日志前缀
| 标记 | 含义 | 使用场景 |
|------|------|---------|
| ✅ | 成功完成 | API调用成功、操作成功 |
| ❌ | 失败/错误 | 验证失败、取消失败 |
| 📝 | 记录/标记 | 标记订单操作 |
| ⚠️  | 警告/注意 | 取消订单操作 |
| 🚨 | 严重问题 | 系统关键错误 |
| 📋 | 查询/列表 | 查询操作开始 |
| 📄 | 详情/细节 | 获取详情 |
| ⭐ | 关键操作 | API调用标记 |

### 日志级别
- **INFO** - 正常操作、查询开始
- **WARN** - 订单标记、订单取消、登录失败
- **ERROR** - 业务逻辑失败、系统错误

### 示例日志输出
```
[INFO]  ✅ Orders queried successfully: page=1, totalElements=150, totalPages=8
[WARN]  📝 Admin marking order: orderId=123, riskFlag=SUSPICIOUS, adminId=5, timestamp=2024-07-26 14:30:00
[WARN]  ⚠️  Admin cancelling order: orderId=123, reason=异常交易, adminId=5, timestamp=2024-07-26 14:31:00
[WARN]  ⚠️  Login failed: username=user123, reason=INVALID_PASSWORD, ip=192.168.1.1
[ERROR] ❌ Cannot cancel order with status: FILLED
[INFO]  ⭐ Critical API called: POST /admin/orders/123/cancel by user=admin, responseTime=145ms, code=200
```

# 券商环境切换与 API 接入设计

## 1. 目的与边界

定义 FlashTrade 从本地 Mock、券商 Sandbox 到生产 API 的安全切换方式。切换只影响后端 Adapter；Flutter、Web 和获授权 API 客户端始终调用 FlashTrade 后端，不直接访问券商。

本设计不代表外部券商 API 已接入。当前实现阶段固定使用 Mock，不连接 Sandbox、生产券商、真实账户或外部行情服务。

## 2. 模式模型

运行模式沿用 `t_broker_runtime_config.mode` 中的值：

| 模式 | 含义 | 对外网络请求 |
|---|---|---|
| `MOCK` | 本地/隔离模拟数据与操作 | 不允许 |
| `SANDBOX` | 券商提供的测试环境 | 只有部署明确允许且对应 Adapter 完成验收后才允许 |
| `PRODUCTION` | 券商生产环境 | 只有独立授权、风险审批及发布门通过后才允许 |

`mock_enabled` 是兼容字段，必须与 `mode` 一致：仅 `MOCK` 可为 `true`。配置不一致或未知时安全回退为 `MOCK`，并记录服务端告警日志；不得按 URL、凭证是否存在来推断模式。

## 3. 配置优先级与切换

采用两层约束：

1. **部署允许模式**由受控的服务端环境配置决定，是最高权限边界。数据库和管理 UI 不能扩大允许范围。
2. **券商当前模式**由数据库 `t_broker_runtime_config` 按券商保存，只能在部署允许范围内选择。

规则如下：

- 本地开发和测试部署只允许 `MOCK`，不论数据库、账户绑定或券商属性中的旧值是什么。
- Sandbox 部署可按券商允许 `MOCK`、`SANDBOX`；某券商的 Sandbox Adapter、端点和凭证未完成专项验收前，不应将其加入允许集合。
- 生产部署只有在单独授权后才允许对应券商的 `PRODUCTION`。不允许因数据库被修改、凭证存在或管理端操作而隐式开放。
- 没有数据库配置、配置无法读取、模式无效或与允许集合不符时，采用 `MOCK` 或安全失败；不得回退到生产端点。
- 环境切换通过部署配置和受控发布进行。高风险环境不允许从用户请求参数选择模式。

当前默认配置：

```yaml
app:
  broker:
    allowed-modes: MOCK
```

进入 Sandbox 阶段后，只有完成对应券商 Adapter、Sandbox URL、凭证和测试验收，才在该环境的受控配置中增加 `SANDBOX`；生产模式同理，必须单独审批后开放 `PRODUCTION`。不应为了方便在共享的开发配置中开放外部模式。

数据库 repeatable seed 已将 `ETRADE`、`SCHWAB`、`TASTYTRADE`、`TASTYWORKS` 初始化为 `MOCK` 且 `mock_enabled=1`。该 seed 用于初始化/维护 Mock 配置，不是开放外部 API 的授权机制。

## 4. API 地址与凭证

- API 主机和 OAuth/Session 端点由后端按券商及部署环境配置；不得接受前端传入 URL，也不得以数据库中的任意 `base_url` 作为网络目标。
- `base_url` 字段为既有数据库兼容字段。运行时使用券商属性和所选部署环境的固定配置；切换环境时使用经过审核的环境配置，不由管理 UI 自定义 URL。
- 管理 API 不读取或回显数据库/API 配置中的 URL；页面只展示有效模式与是否会发起外部请求。
- API key、client secret、OAuth refresh/access token、Session Token 等秘密通过环境变量或密钥管理系统注入。数据库只保存非秘密的模式、券商配置和必要的秘密引用；普通日志、API 响应及前端不得出现秘密。
- 需要分别确认各券商的认证、令牌刷新/撤销、账户授权、市场数据权限和 Sandbox 规则。仅有 URL 和 key 不足以完成接入。
- 现有实现已体现券商认证差异，例如 Schwab OAuth 配置、E*TRADE OAuth 1.0a，以及 Tastyworks Session Token；Adapter 应继续封装提供方差异。

## 5. 请求路由

1. 用户请求先由 FlashTrade 后端完成身份、角色/Scope、账户归属、输入、风控和幂等校验。
2. 后端从已授权账户映射取得券商标识；不能信任客户端传入券商模式或目标 API URL。
3. 配置服务解析该券商的有效模式，并校验其在当前部署允许集合内。
4. `MOCK` 路由到本地 Mock 实现；`SANDBOX`/`PRODUCTION` 只路由到该券商、该部署环境对应的 Adapter 与固定端点。
5. 不同环境的凭证、账户、数据库数据和日志严格隔离。Mock 或 Sandbox 故障时不得自动降级/升级到其他环境。

## 6. 交易失败语义

- 写请求超时、断网或响应丢失时，交易结果为未知状态；先查单/对账，不得盲目重复提交。
- 下单、撤单继续使用服务端风控、资源归属检查、幂等键和审计。切换模式不会绕过这些校验。
- Sandbox 的成功响应不是生产订单；UI 和日志必须显示真实环境及数据来源，避免将测试结果误认为真实成交。

## 7. 管理与运维

- 管理端只展示服务端返回的有效模式与状态，不提供绕过部署允许集合的切换或自定义 URL 功能。
- 模式变更记录操作者、时间、券商、旧/新模式、审批/变更单标识和结果；不得记录凭证。
- 开放 Sandbox 前逐券商完成认证、行情、账户、下单、撤单、查单、限流、超时/未知状态和隔离测试。
- 开放生产前另行完成明确授权、凭证管理、风险审批、操作确认、审计告警、限流、回退和专项验收。
- 当前 `MOCK` 阶段不执行任何外部网络调用。打开 Sandbox 或生产模式不得作为常规开发调试手段。

## 8. 当前实现与后续阶段

当前阶段：

- `MOCK` 是默认且唯一允许模式。
- 开发/测试环境强制 `MOCK`，管理端数据库配置不能切换到 Sandbox 或生产。
- 券商端点由服务端属性提供，数据库 URL 不作为请求目标。
- 后端保留 `BrokerMode`、允许模式校验及按券商读取模式的扩展点；此阶段不开放外部模式。

后续顺序：

1. 完成本地 Mock 的 API、Flutter、Web 纵向闭环及验收。
2. 针对选定券商单独评审并实现 Sandbox Adapter，配置隔离的测试账户和固定 Sandbox 端点，逐项验收。
3. 只有 Sandbox 验收通过、取得生产授权并完成风险/运维审批后，才实现并开放生产连接。

## 9. 验收用例

- 开发/测试配置为 MOCK 时，四种已配置券商均不触发外部 API；健康检查也不触发外部请求。
- 数据库尝试将模式改为 `SANDBOX`/`PRODUCTION` 或写入任意 URL，在当前部署下被服务端拒绝。
- 允许集合不含某模式时，读取到该模式也不能触发对应 Adapter。
- 允许集合明确含某券商 Sandbox 模式时，仍只使用固定 Sandbox 端点和 Sandbox 凭证；不得访问生产端点。
- 模式值未知、数据库不可用或模式与 `mock_enabled` 不一致时，不得按生产模式继续执行。
- 越权账户、重复订单、风控拒绝、超时/结果未知等场景，在切换模式前后仍由后端一致处理。

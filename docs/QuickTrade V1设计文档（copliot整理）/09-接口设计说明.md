# 09-接口设计说明

## 1. 目标

本文件用于定义 QuickTrade V1 的后端接口设计范围，目标是让前端、后端和 Adapter 层使用统一的接口约定，避免各自实现不一致。

## 2. 接口设计原则

- 前端只依赖 QuickTrade 的统一接口，不直接依赖 Broker 原始接口
- 所有接口返回统一格式，便于前端统一处理
- Broker 相关差异由 Adapter 层处理
- 接口命名要简洁、稳定、便于扩展

## 3. 统一响应格式

所有接口建议采用统一响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

### 3.1 响应字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 响应状态码，成功为 200 |
| message | string | 响应说明 |
| data | object | 返回数据主体 |

## 4. 接口清单

### 4.1 用户与会话

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/auth/login | POST | 登录 Broker 账户 |
| /api/auth/logout | POST | 登出当前账户 |
| /api/auth/session | GET | 获取当前会话信息 |

### 4.2 行情

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/quotes/{symbol} | GET | 获取指定股票的实时行情 |
| /api/quotes/search | GET | 搜索股票 |
| /api/market/status | GET | 获取市场状态 |

### 4.3 订单

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/orders | POST | 提交订单 |
| /api/orders/{orderId} | GET | 查询订单详情 |
| /api/orders/{orderId}/cancel | POST | 撤销订单 |
| /api/orders/{orderId}/replace | POST | 修改订单 |
| /api/orders | GET | 查询订单列表 |

### 4.4 持仓与账户

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/positions | GET | 获取当前持仓 |
| /api/account | GET | 获取账户摘要 |
| /api/account/cash | GET | 获取现金余额 |
| /api/account/buying-power | GET | 获取购买力 |

### 4.5 自选股

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/watchlist | GET | 获取自选股列表 |
| /api/watchlist | POST | 添加自选股 |
| /api/watchlist/{symbol} | DELETE | 删除自选股 |

> 说明：如果当前券商支持 Watchlist API，则后端可以优先通过该券商接口同步自选股；否则由 QuickTrade 本地 `WatchListService` 提供自选股管理。
> 
> 当前已完成 Tastytrade 自选股列表后端适配，并补充了 `flash-trade-mock` 中 Tastytrade Watchlist API 的 mock 支持。

## 5. 接口详情

### 5.1 登录接口

#### 请求

```http
POST /api/auth/login
Content-Type: application/json
```

```json
{
  "brokerType": "TASTYTRADE",
  "username": "demo",
  "password": "***"
}
```

#### 响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "brokerType": "TASTYTRADE",
    "accountId": "acct-001",
    "expiresAt": "2026-07-11T12:00:00Z"
  }
}
```

### 5.2 行情接口

#### 请求

```http
GET /api/quotes/AAPL
```

#### 响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "symbol": "AAPL",
    "lastPrice": 212.35,
    "bidPrice": 212.34,
    "askPrice": 212.36,
    "open": 210.10,
    "high": 213.20,
    "low": 209.90,
    "close": 211.80,
    "volume": 1250000
  }
}
```

### 5.3 下单接口

#### 请求

```http
POST /api/orders
Content-Type: application/json
```

```json
{
  "symbol": "AAPL",
  "side": "BUY",
  "quantity": 100,
  "price": 212.35,
  "orderType": "LIMIT"
}
```

#### 响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "orderId": "ord-001",
    "symbol": "AAPL",
    "side": "BUY",
    "quantity": 100,
    "price": 212.35,
    "status": "PENDING",
    "orderType": "LIMIT"
  }
}
```

## 6. 错误码建议

| 错误码 | 含义 |
| --- | --- |
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录或会话失效 |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 409 | 业务冲突，例如订单重复提交 |
| 500 | 服务端内部错误 |
| 502 | Broker 服务调用失败 |

## 7. 备注

- 未来如果新增 Broker，只需要在 Adapter 层新增实现，接口层保持不变
- 前端对接口的依赖应该建立在 QuickTrade 的统一接口之上
- 所有关键交易动作都需要记录日志与异常信息

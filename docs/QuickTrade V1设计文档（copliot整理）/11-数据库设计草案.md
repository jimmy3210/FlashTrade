# 11-数据库设计草案

## 1. 目标

本文件用于定义 QuickTrade V1 中需要落库的数据对象，重点覆盖用户基础、Broker 账户元数据、用户偏好、自选股、会话，以及现有后端的交易同步快照。

## 2. 设计原则

- 交易相关实时数据优先从 Broker 获取，本地数据库以快照、配置和元数据为主
- 本地数据库主要用于保存用户配置、Broker 账户绑定、本地自选、会话与系统配置
- 现有后端已实现的业务表应纳入设计并沿用，新增表应补齐前端需求
- 表结构保持清晰，采用少量关联，避免过早复杂化

## 3. 当前已实现表

当前 `flash-trade-api` 后端已经通过 Flyway 实现以下表：

- `users`
- `positions`
- `orders`
- `trades`
- `t_broker`
- `t_broker_dev_account`
- `t_broker_account`
- `t_broker_account_permission`

其中 `positions/orders/trades` 为 Broker 同步快照表；
`t_broker*` 系列为 Broker 元数据与用户券商账户管理表。

### 3.1 users

用户基础信息表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| username | varchar(50) | 用户名 |
| password_hash | varchar(255) | 密码哈希 |
| role | varchar(20) | 用户角色 |
| enabled | tinyint(1) | 是否启用 |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

### 3.2 t_broker / t_broker_dev_account / t_broker_account / t_broker_account_permission

现有后端已实现的 Broker 元数据与账户管理表。

- `t_broker`: 券商基础信息
- `t_broker_dev_account`: 开发者 API Key/Secret
- `t_broker_account`: 用户券商账户绑定
- `t_broker_account_permission`: 券商账户权限

这四张表已能承载文档中的 `broker_accounts`、`broker_type` 与权限管理需求。

## 4. 建议补齐表

为了与 QuickTrade 统一接口和前端功能对齐，建议补齐以下表：

### 4.1 watchlists

自选股表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 所属用户 |
| broker_id | bigint | 券商标识，关联 `t_broker` |
| symbol | varchar(20) | 股票代码 |
| sort_order | int | 排序顺序 |
| created_at | datetime | 创建时间 |

> 说明：即使使用券商 Watchlist API，同样建议在本地保存 `broker_id` 与 `symbol`，以支持统一数据模型、离线访问和本地缓存。
> 
> 当前已实现 Tastytrade Watchlist 后端同步逻辑，`watchlists` 表中已保留 `broker_id`/`broker_name` 元数据以支持统一数据模型。
### 4.2 user_settings

用户设置表。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 所属用户 |
| theme | varchar(20) | 主题（dark/light） |
| refresh_interval | int | 刷新间隔秒数 |
| default_broker | varchar(50) | 默认 Broker |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

### 4.3 session_tokens

会话信息表，可用于持久化 Broker 登录会话或授权 token，作为 Redis 缓存的补充。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | bigint | 主键 |
| user_id | bigint | 所属用户 |
| broker_id | bigint | 对应 `t_broker.id` |
| broker_account_id | bigint | 对应 `t_broker_account.id` |
| token | text | 会话 token |
| expires_at | datetime | 过期时间 |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

> 说明：当前后端 Tastyworks 会话 token 由 Redis 缓存管理，建议加一层 DB 持久化以便更可靠地回填历史、审计和分布式恢复。

## 5. 建议改进点

### 5.1 保持现有 Broker 快照表

当前后端已实现的 `positions/orders/trades` 表适合保留为 Broker 数据快照：

- `positions`：持仓快照
- `orders`：本地委托记录与同步订单状态
- `trades`：成交历史

这些表不应作为前端实时数据源的唯一来源，而是用于历史查询、回溯、聚合计算与审计。

### 5.2 统一 Broker 账户表命名

当前后端使用 `t_broker_account`，文档中使用 `broker_accounts`。建议：

- 继续保留 `t_broker_account` 以兼容现有实现
- 在文档层面将其说明为“Broker 账户绑定表”
- 未来可通过视图或别名将其映射为 `broker_accounts`

### 5.3 将账户映射从配置迁移到 DB

当前代码的 `BrokerSyncProperties` 仍从 `application.yml` 读取账户列表。
建议将用户与 Broker 账户映射逐步迁移到 `t_broker_account`，让数据库成为“账户绑定的单一可信来源”。

### 5.4 补齐本地用户与偏好数据表

`watchlists`、`user_settings` 与 `session_tokens` 三张表是 QuickTrade 统一接口层的必要补充。

- `watchlists` 为自选股功能提供本地存储
- `user_settings` 为界面偏好和默认券商存储提供支持
- `session_tokens` 为 Broker 会话缓存提供可审计的持久层

## 6. 表关系

- `users` 与 `t_broker_account`：一对多
- `users` 与 `watchlists`：一对多
- `users` 与 `user_settings`：一对一
- `users` 与 `session_tokens`：一对多
- `t_broker` 与 `t_broker_account`：一对多
- `t_broker_account` 与 `t_broker_account_permission`：一对多

## 7. 建议索引

- `watchlists.user_id`
- `watchlists.symbol`
- `t_broker_account.user_id`
- `t_broker_account.account_no`
- `session_tokens.user_id`
- `session_tokens.expires_at`
- `orders.user_id`
- `trades.user_id`

## 8. 说明

V1 中数据库的主要职责为：

- 保存平台用户与认证信息
- 保存 Broker 元数据与用户券商账户绑定
- 保存本地自选股、偏好和会话状态
- 保存 Broker 数据同步快照（持仓/委托/成交）

实时行情、下单、持仓状态等业务应优先依赖 Broker API，数据库在本地提供补充与历史视图。

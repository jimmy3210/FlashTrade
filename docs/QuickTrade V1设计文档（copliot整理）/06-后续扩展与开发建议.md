# 06-后续扩展与开发建议

## 1. V2 扩展方向

V1 完成后，可以按照以下方向继续扩展：

- 历史 K 线
- Scanner
- 条件单与价格提醒
- 期权链
- 多账户管理
- 新闻与公告
- 更丰富的账户与风控信息

## 2. 开发建议

### 2.1 优先顺序

建议优先按以下顺序推进：

1. 完成 Broker Adapter 和统一数据模型
2. 实现基础行情、下单、持仓和账户服务
3. 再推进前端页面与交互细节
4. 最后补充测试、异常处理与日志能力

### 2.2 架构建议

- 保持 UI 与 Broker 解耦
- 用统一服务层封装业务能力
- 为每个 Broker 提供独立 Adapter
- 避免将 Broker 字段直接写入 UI 逻辑

### 2.3 数据与接口建议

- 自选股、用户配置等本地数据由 QuickTrade 自己管理
- 实时行情与订单相关数据优先从 Broker 获取
- 对外接口尽量保持稳定，方便后续替换 Broker

## 3. 交付建议

为了后续维护和扩展更顺利，建议把 V1 的文档、接口和代码约定一起固化：

- 文档：明确功能边界与字段映射
- 接口：统一命名与返回结构
- 代码：避免 Broker 逻辑散落在 UI 或业务层
- 测试：至少覆盖常见下单、查询和异常场景

## 4. 总结

QuickTrade V1 的关键不是“做很多功能”，而是“用最小但足够完整的能力，建立一个可持续扩展的交易客户端基础设施”。

# 08-开发实施顺序与角色分工

## 1. 目标

本文件用于帮助团队明确 QuickTrade V1 的开发节奏、责任边界和优先级，避免前后端在设计阶段各自理解不一致。

## 2. 推荐开发顺序

### 第一阶段：基础设计与数据模型

- 确认 V1 功能范围
- 确定统一数据模型
- 确认 Broker Adapter 的输入输出契约
- 形成接口草案与字段映射表

### 第二阶段：后端服务与适配层

- 实现登录与会话管理
- 实现行情服务、订单服务、持仓服务和账户服务
- 完成 Schwab / Tastytrade 的 Adapter 实现
- 输出统一的 QuickTrade 服务接口

### 第三阶段：前端界面与交互

- 根据 UI 说明书完成页面布局
- 完成 Watch List、Quote、Order Entry、Positions、Orders、Account Summary 的展示
- 接入统一服务层接口
- 完成基本交互和状态反馈

### 第四阶段：测试与验收

- 完成功能测试与异常流程测试
- 验证订单、行情和账户查询的稳定性
- 根据功能清单完成 V1 验收

## 3. 角色分工建议

| 角色 | 主要职责 |
| --- | --- |
| 产品 / 设计 | 维护功能范围、交互说明、页面目标 |
| 前端开发 | 实现 UI、状态管理、接口调用与可视化展示 |
| 后端开发 | 实现服务层、Adapter、业务逻辑与接口暴露 |
| 测试 | 编写测试用例、覆盖核心流程并验证结果 |
| 架构负责人 | 维护整体设计约束、接口规范和扩展方向 |

## 4. 开发建议

- 先完成“能跑通的最小闭环”再扩展功能
- 优先保证行情、下单、持仓和账户这四类核心能力
- 将 Broker 差异控制在 Adapter 层，避免散落在 UI 和业务层
- 每一阶段完成后应同步更新文档，保证文档与实现一致

## 5. 交付标准

V1 可视为交付成功的标准包括：

- 用户可以登录 Broker 账户
- 用户可以查看实时行情
- 用户可以完成买入 / 卖出
- 用户可以查看持仓与账户摘要
- 文档与实现对齐，便于后续扩展

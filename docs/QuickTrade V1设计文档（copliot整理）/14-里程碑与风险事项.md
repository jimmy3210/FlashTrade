# 14-里程碑与风险事项

## 1. 目标

本文件用于梳理 QuickTrade V1 的开发里程碑、关键风险点和应对建议，便于团队按阶段推进并控制交付风险。

## 2. 推荐里程碑

| 里程碑 | 目标 | 预期产出 |
| --- | --- | --- |
| M1 | 完成需求与设计确认 | 设计文档、接口草案、数据模型 |
| M2 | 完成后端基础能力 | 登录、行情、订单、持仓、账户服务 |
| M3 | 完成前端基础页面 | UI 布局与核心交互 |
| M4 | 完成联调与测试 | 前后端联调、异常处理、验收测试 |
| M5 | 完成 V1 交付 | 可演示版本、验收结论与交付文档 |

## 3. 关键风险事项

| 风险点 | 影响 | 建议应对 |
| --- | --- | --- |
| Broker API 差异过大 | 导致适配成本高 | 先统一抽象模型，再做 Adapter |
| 实时行情接口不稳定 | 影响 UI 与订单体验 | 增加重试、缓存和错误提示 |
| 订单流程复杂 | 容易产生误操作 | 强制预览、确认和状态反馈 |
| 前后端接口定义不一致 | 导致联调成本高 | 先定统一接口格式与字段模型 |
| 数据库设计过度复杂 | 影响实施节奏 | V1 先聚焦必要实体，避免过度设计 |

## 4. 建议控制措施

- 先完成最小闭环，再扩展功能
- 关键功能优先开发，非核心功能延后
- 对 Broker 失败场景提前设计兜底逻辑
- 每阶段结束后进行一次文档与实现对齐检查

## 5. 交付建议

V1 的核心目标不是“功能最多”，而是“基础交易闭环可稳定运行”。因此建议把交付标准聚焦在：

- 能登录账户
- 能看行情
- 能下单
- 能看持仓与账户
- 能顺利完成一次完整交易流程

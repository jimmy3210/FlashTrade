## 🧪 集成测试场景

### 场景 1：用户账户绑定流程

#### 前置条件
- ✅ 系统已启动 (后端 + 前端)
- ✅ 管理员账户已登录
- ✅ 至少存在一个用户和一个 ACTIVE 状态的券商账户

#### 测试步骤

**Step 1: 访问账户绑定页面**
```
1. 打开前端管理系统: http://localhost:5173/quicktrade/admin/
2. 登录（用户名: admin, 密码: 根据系统配置）
3. 在左侧菜单点击"账户绑定"
4. 预期：加载用户下拉列表和可用账户列表
```

**Step 2: 选择用户**
```
1. 在用户下拉框选择 "trader01"
2. 预期：
   - 显示该用户的当前绑定账户信息（如已绑定）
   - 或显示"该用户未绑定任何账户"（如未绑定）
```

**Step 3: 切换账户**
```
1. 在可用账户列表中找到一个 ACTIVE 账户（不是当前绑定的）
2. 点击该账户的"切换"按钮
3. 确认对话框显示: "确认将用户 trader01 绑定到账户 {accountNo}?"
4. 点击确认
5. 预期结果：
   - API 响应成功 (200 OK)
   - 页面显示成功提示
   - 当前绑定账户信息自动更新
   - 旧账户若仍在列表，其按钮应变为"切换"（而非"当前"）
```

**Step 4: 验证数据库**
```sql
-- 验证绑定是否成功
SELECT id, username, current_broker_account_id 
FROM users 
WHERE username = 'trader01';

-- 预期：current_broker_account_id 应指向新账户 ID

-- 验证账户的绑定用户
SELECT id, account_no, 
  (SELECT username FROM users WHERE current_broker_account_id = t_broker_account.id) AS bound_user
FROM t_broker_account 
WHERE id = {新账户ID};

-- 预期：bound_user 应为 'trader01'
```

## 🐛 故障排查

### 问题 1: 用户查询当前账户返回 404

**症状**:
```json
{
  "success": false,
  "error": "用户未绑定券商账户: 5",
  "errorCode": "RESOURCE_NOT_FOUND"
}
```

**原因分析**:
- ❌ 用户 ID 不存在
- ❌ 用户存在但 `current_broker_account_id` 为 NULL
- ❌ `current_broker_account_id` 指向的账户已被删除

**排查步骤**:

```sql
-- 1. 检查用户是否存在
SELECT id, username, current_broker_account_id FROM users WHERE id = 5;

-- 如果查询无结果，用户 ID 错误
-- 如果 current_broker_account_id 为 NULL，用户未绑定

-- 2. 如果 current_broker_account_id 不为 NULL，检查账户是否存在
SELECT id, account_no FROM t_broker_account WHERE id = {current_broker_account_id};

-- 如果查询无结果，账户已被删除（脏数据）
-- 解决：手动修复
UPDATE users SET current_broker_account_id = NULL WHERE id = 5;
```

**解决方案**:
1. 确认用户 ID 正确
2. 在前端 UserBrokerBinding 页面为用户绑定一个账户
3. 若数据库数据不一致，执行上述 UPDATE 修复

### 问题 2: 绑定账户时返回"该券商账户已被其他用户绑定"

**症状**:
```json
{
  "success": false,
  "error": "该券商账户已被其他用户绑定",
  "errorCode": "INVALID_ARGUMENT"
}
```

**原因分析**:
- ✅ 账户确实已被其他用户绑定
- ⚠️ 数据库数据不一致

**排查步骤**:

```sql
-- 1. 查看该账户的绑定用户
SELECT id, username, current_broker_account_id 
FROM users 
WHERE current_broker_account_id = {accountId};

-- 应返回恰好 1 行或 0 行

-- 2. 如果返回多行，则存在数据不一致
-- 原因可能是之前的事务未正确完成
```

**解决方案**:
1. 若要覆盖绑定，先停用该账户，再创建新账户
2. 或联系管理员人工调整（执行 UPDATE）

### 问题 3: 前端切换账户后，列表未更新

**症状**:
- 点击"切换"按钮后显示成功
- 但页面的"当前使用者"列仍未改变

**原因分析**:
- ✅ API 调用成功，但前端未刷新数据

**排查步骤**:

```typescript
// 检查 UserBrokerBinding.vue 中的代码
const bindAccount = async (account: any) => {
  // ...
  await loadUserBinding();  // 这一行很关键，必须调用刷新
  // ...
};
```

**解决方案**:
1. 确保 `bindAccount()` 方法在 API 调用成功后调用了 `loadUserBinding()`
2. 手动刷新页面 F5

### 问题 4: 数据库迁移未执行

**症状**:
- 访问绑定页面时报错：`Column 'current_broker_account_id' doesn't exist`
- 或管理后台列表中看不到"当前使用者"列

**原因分析**:
- ❌ V18 数据库迁移未执行

**排查步骤**:

```sql
-- 检查是否执行了 V18 迁移
SELECT * FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 5;

-- 应显示:
-- | version | description | installed_on | execution_time |
-- | V18     | add_current_broker_account_id | ... | ... |
```

**解决方案**:
1. 检查 `flash-trade-api/src/main/resources/db/migration/` 中是否存在 `V18__add_current_broker_account_id.sql`
2. 重启应用，让 Flyway 自动执行迁移
3. 若迁移文件存在但未执行，检查应用日志中 Flyway 的错误信息

### 问题 7: 绑定成功但客户端查询仍失败

**症状**:
```
GET /api/v1/trade/current-account → 200 OK
但数据中 apiEnvironment 为 null 或 LIVE（不是预期的环境）
```

**原因分析**:
- ✅ 绑定成功，但账户的 apiEnvironment 字段未设置
- ⚠️ 或缓存未更新

**排查步骤**:

```sql
-- 检查账户的 apiEnvironment 字段
SELECT id, account_no, api_environment 
FROM t_broker_account 
WHERE id = {accountId};

-- 若 api_environment 为 NULL，则需要更新
UPDATE t_broker_account 
SET api_environment = 'LIVE' 
WHERE api_environment IS NULL;
```

**解决方案**:
1. 在前端创建或编辑账户时，确保选择了 API 环境
2. 若已创建的账户缺少环境信息，在管理后台编辑该账户，设置环境后保存

## 📊 常见错误代码映射

| HTTP 状态 | 错误码 | 说明 | 解决方案 |
|---------|-------|------|--------|
| 200 | - | 成功 | 无 |
| 400 | INVALID_ARGUMENT | 参数错误 | 检查请求参数是否合法 |
| 400 | CONFLICT | 业务冲突 | 账户已被占用，改用其他账户 |
| 401 | UNAUTHORIZED | 认证失败 | 检查 Token 是否有效或过期 |
| 403 | FORBIDDEN | 权限不足 | 检查用户角色（需要 ADMIN 权限） |
| 404 | RESOURCE_NOT_FOUND | 资源不存在 | 检查 ID 是否正确 |
| 500 | INTERNAL_ERROR | 服务器错误 | 查看后端日志 |

## 🚀 性能优化建议

### 数据库索引

```sql
-- 创建索引以加速绑定查询
CREATE INDEX idx_users_current_broker_account_id 
ON users(current_broker_account_id);

-- 创建索引以加速账户查询
CREATE INDEX idx_broker_account_user_id 
ON t_broker_account(user_id);
```

### 前端缓存

```typescript
// 在 Pinia store 中缓存当前账户
export const useAccountStore = defineStore('account', () => {
  const currentAccount = ref<BrokerAccountDto | null>(null);
  const lastFetchTime = ref<number>(0);

  const getCurrentAccount = async (forceRefresh = false) => {
    const now = Date.now();
    
    // 若 1 分钟内已获取，使用缓存
    if (!forceRefresh && currentAccount.value && now - lastFetchTime.value < 60000) {
      return currentAccount.value;
    }

    currentAccount.value = await request.get('/api/v1/trade/current-account');
    lastFetchTime.value = now;
    return currentAccount.value;
  };

  return { currentAccount, getCurrentAccount };
});
```

# FlashTrade 用户-券商账户一对一绑定系统

## 概述

实现了用户与券商账户的**一对一绑定模式**（每个用户同时只能绑定一个券商账户，但可以随时切换）。

## 数据模型

### 核心表结构

```
users 表
├─ id (PK)
├─ username
├─ password_hash
├─ role
├─ enabled
├─ current_broker_account_id (FK) ← 新增字段，指向当前绑定的券商账户
└─ created_at, updated_at

t_broker_account 表
├─ id (PK)
├─ user_id (FK) ← 账户创建者/初始所有者
├─ broker_id (FK)
├─ account_no
├─ account_type (CASH/MARGIN)
├─ status (ACTIVE/SUSPENDED/CLOSED)
├─ dev_account_id
├─ api_environment (LIVE/SANDBOX) ← 账户级 API 环境配置
└─ created_at
```

### 关键约束

- `users.current_broker_account_id` 与 `t_broker_account.id` 建立外键关系
- 一个账户只能被一个用户绑定（通过 current_broker_account_id 的唯一性保证）
- 解绑旧账户时自动设置 `current_broker_account_id = NULL`

## 数据库迁移

### V17: API 环境字段
```sql
ALTER TABLE t_broker_account
    ADD COLUMN api_environment VARCHAR(20) NULL;
UPDATE t_broker_account SET api_environment = 'LIVE' WHERE api_environment IS NULL;
```

### V18: 一对一绑定关系
```sql
ALTER TABLE users
    ADD COLUMN current_broker_account_id BIGINT NULL,
    ADD CONSTRAINT fk_users_current_broker_account
        FOREIGN KEY (current_broker_account_id)
        REFERENCES t_broker_account(id) ON DELETE SET NULL;
```

## 后端 API

### 管理端接口

#### 1. 券商账户管理（BrokerAccountAdminController）

| 方法 | 端点 | 功能 |
|------|------|------|
| GET | `/admin/broker-accounts` | 列表：所有券商账户及其当前绑定用户 |
| GET | `/admin/broker-accounts/{id}` | 详情：单个账户信息 |
| POST | `/admin/broker-accounts` | 创建：新建券商账户 |
| PUT | `/admin/broker-accounts/{id}` | 编辑：更新账户配置 |
| DELETE | `/admin/broker-accounts/{id}` | 删除：停用账户（标记为 CLOSED） |

#### 2. 用户账户绑定管理（BrokerAccountAdminController）

| 方法 | 端点 | 功能 |
|------|------|------|
| GET | `/admin/broker-accounts/user/{userId}/current` | 查询用户当前绑定的账户 |
| POST | `/admin/broker-accounts/user/{userId}/bind/{accountId}` | 为用户设置/切换账户 |

**绑定逻辑**：
- 同一个账户只能被一个用户绑定
- 切换账户时自动解绑用户的旧账户
- 只能绑定状态为 ACTIVE 的账户

#### 3. 响应格式

```json
{
  "success": true,
  "data": {
    "id": 1,
    "userId": 5,
    "username": "trader01",
    "brokerId": 2,
    "brokerCode": "ETRADE",
    "brokerName": "E*TRADE",
    "accountNo": "123456789",
    "accountType": "CASH",
    "status": "ACTIVE",
    "apiEnvironment": "LIVE",
    "devAccountId": 10,
    "currentBindingUsername": "trader01"  // 当前使用者
  },
  "error": null
}
```

## 业务流程

### 场景 1：为新用户分配账户

```
1. 管理员创建新用户 → UserManage
2. 创建或选择现有券商账户 → BrokerAccountList
3. 在 UserBrokerBinding 中
   - 选择该用户
   - 点击"切换"将账户绑定给用户
4. 用户下次登录交易客户端时
   - 客户端调用 GET /api/v1/trade/current-account
   - 获取账户信息和 API 环境 (LIVE/SANDBOX)
   - 自动初始化到该账户进行交易
```

### 场景 2：用户切换账户

```
1. 用户原绑定账户 A (ETRADE)
2. 管理员在 UserBrokerBinding 中
   - 选择该用户
   - 点击账户 B (Schwab) 的"切换"按钮
3. 后端处理：
   - 解绑账户 A (users.current_broker_account_id = NULL)
   - 绑定账户 B (users.current_broker_account_id = B.id)
4. 用户下次刷新客户端
   - 重新查询 current-account 端点
   - 获取新的账户 B 信息
   - 自动切换到账户 B
```

### 场景 3：账户不可用处理

```
1. 账户被停用 (status = CLOSED)
2. 用户再次查询 current-account 端点
   - 获得的账户状态为 CLOSED
   - 客户端应提示用户联系管理员重新分配账户
```

## 技术特点

### 约束设计

1. **一对一关系**：通过 `users.current_broker_account_id` 的唯一性（每行最多一个外键引用）保证
2. **自动解绑**：`ON DELETE SET NULL` 若账户被删除，自动清除用户绑定
3. **级联保护**：FK 约束防止绑定不存在的账户

### 查询优化

**列表查询**包含 3 个 LEFT JOIN：
```sql
SELECT a.*, u.username, b.*, u_bind.username AS current_binding_user
FROM t_broker_account a
LEFT JOIN users u ON a.user_id = u.id              -- 账户创建者
LEFT JOIN t_broker b ON a.broker_id = b.id         -- 券商信息
LEFT JOIN users u_bind ON a.id = u_bind.current_broker_account_id  -- 当前使用者
```

**性能考虑**：
- 所有 JOIN 均为 LEFT，支持账户未被绑定的情况
- 建议在 `users.current_broker_account_id` 上建立索引

## 安全性

### 权限控制

- 管理端所有接口需要 `@PreAuthorize("hasRole('ADMIN')")`
- 交易端接口 `/api/v1/trade/current-account` 需要认证（Bearer Token）

### 数据隔离

- 用户只能查询自己的当前账户（在前端）
- 管理员可查看所有用户的绑定关系

### 验证规则

- 只能绑定 ACTIVE 状态的账户
- 一个账户不能同时绑定多个用户（通过查询验证）
- 绑定前验证用户和账户都存在

## 故障排查

### 问题 1：用户无法查询当前账户

**原因**：用户未绑定任何账户或账户被删除

**解决**：
- 检查 `users.current_broker_account_id` 是否为 NULL
- 在 UserBrokerBinding 页面为用户分配账户

### 问题 2：客户端收到错误的 API 环境

**原因**：交易端尚未集成 `current-account` 端点

**解决**：
- 实现 TradeController 中的环境参数传递
- 确保 BrokerClient 正确切换端点

### 问题 3：管理员看不到"当前使用者"

**原因**：数据库迁移未执行或字段未加载

**解决**：
- 运行 Flyway 迁移 (V18)
- 重启应用刷新缓存
- 检查 BrokerAccountDto 中是否包含 currentBindingUsername 字段

## 监控和维护

### 建议监控指标

1. **未绑定用户数**：`SELECT COUNT(1) FROM users WHERE current_broker_account_id IS NULL;`
2. **账户绑定情况**：`SELECT COUNT(DISTINCT current_broker_account_id) FROM users WHERE current_broker_account_id IS NOT NULL;`
3. **环境分布**：`SELECT api_environment, COUNT(1) FROM t_broker_account WHERE id IN (SELECT DISTINCT current_broker_account_id FROM users) GROUP BY api_environment;`

### 定期审计

- 每周检查是否有孤立账户（status=CLOSED 但仍有用户绑定）
- 监控绑定更换频率（如果异常高可能表示业务流程有问题）
- 验证 API 环境配置的合理性（是否过多 SANDBOX）
